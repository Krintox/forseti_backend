# FORSETI

Cross-rail delegated authority security for agentic payments.

Built for the Mastercard Innovation Challenge at Global Fintech Fest 2026.

- Live prototype: https://forseti-frontend.vercel.app
- API: https://forseti-backend.onrender.com
- Frontend source: https://github.com/Krintox/Forseti_frontend

## The problem

Give an AI agent a payment mandate and it can spend through more than one rail. A card
authoriser, UPI Circle, and an agentic checkout each approve what they can see, and each one is
right about its own rail. Nothing in that flow holds the total.

That gap is the starting point, not the contribution. What follows from it is the harder
question: a mandate is not just a number. It carries a purpose, a merchant scope, a counterparty,
a rail list, a per-transaction cap and an expiry. An agent can stay under budget and still act
outside what the person granted.

FORSETI tracks all seven of those dimensions and gives each one its own invariant.

## Read this before you read the code

`INV_01` is the budget check. It adds four exposure buckets and compares the sum to a ceiling:

```
settled + authorized + pending + reserved + new_amount  <=  ceiling
```

Six lines in `app/dtl/invariant_engine.py`. No model, nothing fitted, nothing to tune. You could
write it in a minute, and you should assume we know that. It is in here for two narrow reasons.
It shows the gap is real, and because it is arithmetic rather than a learned threshold it cannot
quietly degrade when an attack family it has never seen shows up.

Treat it as the floor. The work that took real effort is everywhere else.

## What is actually built

| Module | What it does |
|---|---|
| `app/intent_firewall/` | Compiles a stated purpose into a policy object, then scores drift between what was authorised and what the cart actually is. Emits `ALLOW`, `PARTIAL_DRIFT` or `HARD_DRIFT` with the drift vector that produced it. |
| `app/deception_lab/` | Detectors for attacks aimed at the agent rather than the payment: prompt injection, tool output poisoning, context and memory poisoning, authority impersonation. Deliberately kept as observability, never as the authorization boundary. |
| `app/graph_sentinel/` | Builds a cross-authority entity graph over devices, merchants and beneficiaries, then derives PageRank, community and centrality features. Catches rings that look unrelated one transaction at a time. |
| `app/kill_chain/` | Maps an attempt onto the stage of the agentic payment lifecycle it lands in, and scores how far it got before something stopped it. |
| `app/detector/` | The learned side. 37 features in six groups, chronological split, two attack families held out of training, isotonic calibration, real SHAP, and a leakage audit that fails CI if a categorical shortcut reappears. |
| `app/feedback/` | The closed loop. Red re-scores its own strategies from the containment and detection it observed, Blue adapts policy, and the next round starts from that state. |
| `app/dtl/` | The ledger, the seven invariants, the beneficiary directory, the attested SKU catalogue, and the cost governor that contains without locking the customer out. |
| `app/settlement/` | Post-authorization reconciliation. Settlement conflict and reconciliation drift, modelled deterministically. |
| `app/crypto/` | ML-DSA-44 (NIST FIPS 204) signing over a canonicalised snapshot that commits to the hash-chained event log head. |
| `app/fidelity/` | KS, Jensen-Shannon divergence, correlation distance, a synthetic-versus-real discriminator and TSTR. Runs, but reports `NOT RUN` because the anchor datasets are licensed. |
| `app/tokenization/` | Token lifecycle and store, including re-scoping an issued token when the principal narrows their grant. |
| `app/simulator/` | Three standards-inspired rail adapters over a full auth, capture, settle, refund lifecycle with two-phase exposure. |
| `app/ai/` | Eleven advisory helpers. None of them can authorise anything. Every output is schema validated and re-checked by the deterministic engine. |

## What the numbers say

All figures come from `artifacts/`, seed 42, regenerated by `python tasks.py all`.

| Metric | Value |
|---|---|
| PR-AUC, temporal test | 0.9209 |
| ROC-AUC | 0.9766 |
| F1 | 0.8772 |
| Recall at 0.5% FPR | 0.8226 |
| Calibration ECE, before and after | 0.01377 to 0.00611 |
| Full inline pipeline, p99 over 10,000 tx | 0.879 ms |

The result worth arguing about is what happens when you withhold an attack family entirely and
then test on it:

| Architecture | Recall, family held out | Family seen |
|---|---|---|
| Rules only | 0.391 | 0.391 |
| Per-rail ML, no cross-rail view | 0.172 | 0.500 |
| Global ML, no DTL features | 0.172 | 0.563 |
| Hybrid ML with DTL aggregate features | 0.828 | 0.844 |
| Deterministic invariant | 0.844 | 0.844 |

Read the middle rows, not the bottom one. A model with no cross-rail view sits at 0.172 held out
and still only reaches about 0.5 when you train it directly on the attack. The information is not
inside any single transaction. Give the same model the aggregate and it reaches 0.828 on a family
it has never seen, with `exposure_after_tx_ratio` as its top SHAP feature.

Measured feature lift from the DTL group: +0.2302 PR-AUC (0.7261 to 0.9563). It holds at the
deployed 0.5 threshold too, not only in threshold-free ranking.

We got this wrong once and left the record in. An earlier run reported 0.000 recall for every
learned model. That was a categorical leak in our own generator, where four of six families
carried a merchant category that never appeared in legitimate traffic. The generator is fixed and
the check now runs in CI. Write-up is in `docs/LEARN_22_THE_LEAK.md`.

## Run it

```bash
pip install -r requirements.txt
cp .env.example .env        # optional, only the advisory AI layer needs keys
python tasks.py all         # regenerates every artifact, about 25 seconds
python tasks.py test        # 455 tests
uvicorn app.main:app --reload
```

Individual stages: `python tasks.py train | evaluate | ablation | fidelity | benchmark | demo`

Change the seed and the data changes while the run stays reproducible: `SEED=123 python tasks.py all`.

The AI helpers are optional. Pull every API key out and the security engine behaves exactly the
same, you just lose the written explanations.

## Limits

1. Statistical fidelity reports `NOT RUN`. The harness works, but PaySim and the ULB card dataset
   are licensed and are not redistributed here, so we make no realism claim at all.
2. The cross-rail holdout slice is 64 transactions. The gap between having the aggregate feature
   and not having it is far wider than the interval and is real. The held-out versus seen gap for
   the classifier is inside the noise, and we do not claim it as generalisation.
3. Everything is measured against our own synthetic adversary, not production fraud.
4. The invariant on its own has a 15.8% false positive rate, mostly legitimate in-scope gift card
   baskets. That is exactly why the cost governor exists instead of a hard block.
5. Not production ready. In-memory state, single process, development keys, no HSM, no
   persistence layer.

## Data safety

No real PAN, CVV, bank account or UPI credential exists anywhere in this repository. Every
identity, merchant and cart is synthetic. No production payment API is contacted and no money
moves. Keys are development only and git-ignored. Licensed datasets are never redistributed.

See `docs/RESPONSIBLE_RESEARCH.md`.
